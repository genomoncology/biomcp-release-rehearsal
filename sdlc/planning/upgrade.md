# Upgrade from BioMCP 0.9 to 1.0

This note describes the 1.0 migration. Install BioMCP through your existing [distribution channel](release.md). Retain the `biomcp-cli` package name, `biomcp` command and stdio `serve` argument. MCP clients call the single `biomcp` tool with the CLI argument array; replace bindings to the old separate typed tools. JSON is the default CLI output. Use `--format md` for Markdown or `--format json` to override configuration.

Section names, aliases and global flags lie outside that ledger; each slice's linked investigation covers them. Deferred rows identify capabilities unavailable in 1.0.

## Configuration and keys

Create `biomcp/config.json` under `$XDG_CONFIG_HOME`, or under `$HOME/.config` when that variable is absent. On Windows use `%APPDATA%/biomcp/config.json`. The configuration is JSON and rejects unknown fields. Move settings deliberately; do not copy a 0.9 configuration wholesale.

```json
{
  "format": "json",
  "disable_sources": [],
  "keys": {
    "oncokb_api_key": "YOUR_ONCOKB_KEY",
    "ncbi_api_key": "YOUR_NCBI_KEY",
    "semantic_scholar_api_key": "YOUR_SEMANTIC_SCHOLAR_KEY"
  }
}
```

Register each key with `biomcp key set <source>`, which prompts for the key, keeps it out of shell history and writes it to this file. Omit unused keys. The environment variables keep their 0.9 names: `ONCOKB_TOKEN`, `NCBI_API_KEY`, `S2_API_KEY`, `NCI_API_KEY`, `OPENFDA_API_KEY`, `ORCID_ACCESS_TOKEN`, `UMLS_API_KEY` and `ALPHAGENOME_API_KEY`. The [legacy-key ruling](../decisions/2026-10-25-legacy-key-names.md) preserves these spellings; a retained name does not promise an implemented source. Stored file values override environment values. The 0.9 DisGeNET credential has no 1.0 gene section; the gene slice ruling drops that section. Keep credentials local and outside version control.

Optional `ncbi_email` identifies NCBI requests. Optional `ca_bundle` names a PEM file that adds company certificates to platform trust. Optional `proxy` names an HTTP or HTTPS proxy and overrides `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY`. Without it, routing uses those environment variables. `disable_sources` accepts individual sources and the `restricted` and `noncommercial` groups; CLI exclusions add to file exclusions. Run `biomcp health` to inspect enabled sources and reachability.

## Hosted clients

The HTTP interface is `biomcp serve --http [ADDR]`, with MCP at `/mcp` and store health at `/health`. The default bind is `127.0.0.1:8080`. A non-loopback listener requires repeatable `--allow-host HOST` arguments or `http.allowed_hosts` in configuration. Foreign hosts and browser origins are refused. Keep public TLS and authentication at your reverse proxy. Source reachability uses `biomcp health`; the HTTP health endpoint makes no source request. The [HTTP decision](../decisions/2026-10-24-1-0-serves-mcp-over-http.md) owns this contract.

## GenCC submissions

The 0.9 `gencc sync` command becomes `biomcp sync gencc`. It installs or refreshes the complete GenCC CSV bundle. `biomcp get gene ODC1 gencc` reads stored submissions by HGNC identity, preserves each source submission and marks stale data. Reads do not synchronize the bundle.

## Trial discovery and documents

`search trial TEXT` sends general registry text; `--condition TEXT` uses the registry condition query, including its native expansions. `--gene`, `--variant` and `--criteria` support discovery and never determine clinical eligibility. `--mutation` and `--biomarker` retire in favor of literal `--variant` text. The semantic therapy-line filters retire with `--criteria` guidance. Registry update dates use `--updated-since` and `--updated-until`. Search offset paging becomes the opaque `--next-page` action; keep the same filters.

ClinicalTrials.gov is the default. Explicit `--source nci` requires the user's NCI key and preserves NCI's own counts and statuses without fallback. NCI condition filters require NCIt identifiers; repeat `--condition` for source-native OR. NCI accepts one `--keyword` for explicit free text and refuses interventions. ClinicalTrials.gov accepts repeated `--condition`, `--intervention` and `--keyword` alternatives joined with OR; different options combine with AND. Unsupported registry-only filters return guidance before any request. Automatic disease resolution is not shipped.

NCI organization discovery adds this command:

| Command | Behavior |
| --- | --- |
| `search organization --source nci` | Use `--name`, `--city`, `--state`, `--country`, `--postal-code`, `--family` or `--lat`/`--lon`/`--distance`. Names are not unique; native counts include every trial status. Search rows carry published details and a next command for `search trial --source nci --facility` with the exact organization name. No organization ID or get command exists. Returned `--pool` page commands retain one bounded observation. |

Use multiple NCT inputs on `get trial` instead of `batch trial`, and trailing section words instead of batch `--sections`. Cards precede requested sections. Every truncated section has its own continuation. A registry reference's type and position do not identify a primary publication. List `get trial NCT documents`, then save one exact manifest filename with `trial document NCT FILE --save PATH`. Documents are downloaded without text extraction. CLI and stdio MCP support saves; HTTP refuses and returns the source URL.

## Variant discovery and source records

`get variant` accepts published rsIDs, CAids, ClinVar Variation IDs and reference-qualified HGVS. Chromosome notation requires `--build`; the old `--assembly` spelling names that replacement. Gene and protein shorthand goes through `search variant --gene SYMBOL --protein CHANGE`; `--hgvsp` names `--protein`. Results preserve every source candidate. Use the returned selection and page argument arrays with their original source-policy settings. No candidate, score or source assertion becomes a BioMCP clinical classification.

Named `get variant ID SECTION` pages call their own source. `predictions` names `predict`, and `population-details` names `variant population ID --detail`. Use `variant assertions CAid --source erepo` for native assertion IDs and versions instead of the old `variant erepo` leaf. Its `--gene` option is dropped; no gene-wide scan replaces missing allele assertions. Use `get variant ID oncokb --build GRCh38 --tumor-type TEXT` instead of `variant oncokb`; missing user keys skip before source access. The product never calls the demo service. The accepted OncoKB source proof uses an approved demo capture. The product still requires the caller's own key. The real ClinVar drug-response label is captured and replayed as native detail.

The old `cbioportal` section names `variant recurrence ID --source cbioportal --gene SYMBOL --study ID --profile ID --sample-set ID`. It has no default cohort. Matched sample counts are page-local and do not supply an assayed denominator. Cancer Hotspots rows remain candidates without an established exact allele join. `variant structure` names `get gene SYMBOL protein`; CGI and variant cspec remain explicitly deferred.

Normalization uses `variant normalize --source car|mutalyzer|variantvalidator|all --hgvs TEXT`; the old positional service and `--input` spelling name this route. VariantValidator and `all` require `--build`. Services preserve independent results, messages and mappings without local repair, transcript choice or consensus.

Only `--review-status`, `--condition` and `--has clinvar` have captured positive advanced-filter mappings. Their literal source fields do not establish that values occur on the same ClinVar submission. Other historical filter mappings are deferred in 1.0. Raw `--query` requires `--source myvariant`, stays unchanged under the default policy and cannot combine with named filters. A component restriction refuses opaque raw queries before source access. Gene/protein selectors require the dbNSFP component; there is no hidden field fallback.

Every source and component starts on with publisher terms. Commercial users should set both `noncommercial` and `restricted` in `disable_sources`. Groups switch off matching aggregator fields while other fields remain available; naming `myvariant` switches off the whole service. CLI exclusions add to configuration exclusions, including for cache, replay and returned next actions. Inspect terms in the response and `health`; public API access grants no additional reuse rights.

A direct dbSNP adapter is dropped from 1.0. rsIDs remain available through MyVariant and the ClinGen Allele Registry with their intermediary provenance.

`search trial --source nci --facility "Dana-Farber Cancer Institute"` filters by exact organization name, case-insensitively. A listed site is not necessarily enrolling. The header carries one matched site and the number of matching sites. Facility and radius filters cannot combine.

## NCI biomarker terminology

| Command | Behavior |
| --- | --- |
| `search biomarker --source nci --name PD-L1` | Search NCI concept names and synonyms with the user's key. Headers retain typed code lists, native type lists and NCI trial counts. Returned page commands retain one bounded observation. |
