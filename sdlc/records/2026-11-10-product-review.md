## Evidence and implementation boundaries

**F1:** `crates/biomcp-query/src/gwas/threshold.rs:154-170` skips an incomparable row; `:189` can finish the walk, `:221` emits `qualifying_total` and `:232-233` classify from a separate refusal flag. `crates/biomcp-adapters/src/gwas/search.rs:154-160` admits ordering without comparing missing values. The exact-threshold contract is the completed exact GWAS threshold ticket. Native refusals combine association and child-record refusals: suppressing an exact count conservatively is sound, but do not claim every refused child means a missing association. The membership-uncertainty flag must survive saved pages and a later clean terminal page. Keep known-zero, equality and underflow controls.

**F2:** `crates/biomcp-query/src/store/pool.rs:150-177` publishes every source pool as current, and `:194-233` extends without reevaluating that eligibility. `source_snapshot.rs:90-106` selects current for no-ID reads. Protein search supplies refused and failed-extension paths at `protein/search.rs:91-104,129-135,181-184`. This contradicts [review stance 1](../decisions/2026-11-06-review-stances.md). Audit protein search/relations, GWAS, pathway, ORCID and study paging. A healthy lazy window remains reusable; complete observation does not mean downloading the whole upstream catalog. Eligibility must come from saved entity state, including refusal flags assigned only during rendering today. Local study pools legitimately have no source outcomes. Atomic updates must protect a newer healthy current mapping from an older or losing writer, and legacy partial mappings need read admission or deliberate invalidation. Raw transport caches remain separate: reconstructing a query need not contact the network. Explicit old failed pools retain their truthful existing status.

**F3:** `crates/biomcp-query/src/drug/search_names.rs:150-190` ignores `mapped.refusals`, while `crates/biomcp-adapters/src/mychem/mod.rs:90-120` discards the native total after a bounded 50-hit lookup. `mychem/names.rs:65-75` can refuse a hit. A ranking comment is not evidence that all exact matching structures fit that prefix. `search_names.rs:211-212` also collapses dropped card results into no match. Carry the available completeness facts, try the existing bounded fallbacks and disclose unresolved identity without claiming proven ambiguity. Do not grow an unbounded scan or a hand-maintained drug dictionary.

**F4:** `crates/biomcp-adapters/src/ctgov/mod.rs:192-203` filters refused studies without carrying their native count. `crates/biomcp-query/src/trial.rs:204-218` uses admitted length for offset and known-total comparison. Preserve `returned` as admitted rows; use native `received` only for source position and end detection. A two-page four-row fixture with one refused first-page row and a redundant final token demonstrates the error.

**F5:** Hosting `src/auth/keys.rs:43-45` returns a matching key before freshness checks; `:70-89` fetches only on a miss. `src/app.rs:69-75` shares this set between session and bearer verification. Token expiry does not bound trust in a compromised signing key capable of issuing another token. The chosen default is five-minute successful-fetch freshness, configurable, with the existing 60-second attempt floor and coalescing. This is a PM security/availability choice, not an issuer SLA. After expiry, an issuer outage returns the existing retryable unavailable response; successful removal yields invalid-token refusal. Verify replacement at the same key ID, concurrent refresh, failed/cancelled attempts and recovery. No production issuer mutation is needed.

**F6:** Fetch `cache.rs:191-202,241-243` turns an oversized selected body into NULL and then deletes it as invalid. `cache_request.rs:230-247` discards expired negative entries into the same offline-miss path used at `:185-201`. The existing tickets already define the bounded fixes and controls; no duplicate tickets were created.

**F7:** README's local source configuration is not fully duplicated in `docs/configuration.md`; deleting it in favor of the existing link alone would lose information. Consolidate deliberately under [review stance 6](../decisions/2026-11-06-review-stances.md), without changing policy or removing first-use guidance. The prepared site still needs to integrate the resulting text.

**F8:** `scripts/nightly_live_check.py` returns only `reason(result, ...)` from `check`, and the retry loop keeps the first reason only when the second attempt succeeds. Both-failure output keeps just the last shortened reason. Emit selected envelope/process diagnostics within an output bound; do not dump full source records, headers or the environment and do not infer wire details absent from the envelope.

Traced paths include GWAS filtering, protein/native query pools, article/trial term expansion and totals, trial token paging, selected variant identity/assembly code, Cellosaurus filtered paging, cache limits/negative expiry, wrapper issuer verification and per-user credentials, source-policy header stripping, stored caller ownership, parsed maintenance restrictions and shutdown ownership. Not run here: the new regression fixtures, loaded multi-tenant cancellation, every entity/filter/format combination, cross-build biological equivalence, real signed hosted accounts, stale-key fake-issuer reproduction, a new full gate or mutation run, every dependency/license/clone/dead-code scan, all shipped channel installs, all site links, or exhaustive adversarial input coverage. Clone/docs scanner tools were unavailable locally; they were not installed merely for this review. The broad source statuses still need the bounded diagnosis in the playbook. No clinical judgment, deployment, account mutation or publication occurred.

The strongest maintainability problems found are concrete repeated contracts: complete membership evidence lost between adapter and query, independent pool owners disagreeing on current-answer eligibility, received versus admitted counts conflated, and external authority cached without a freshness rule. Fix those owners and prove the shared behavior instead of adding per-provider exceptions or layers of release paperwork.
